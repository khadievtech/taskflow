# Architecture Decision Records

Короткие документы, фиксирующие важные архитектурные решения и причины,
по которым они были приняты — включая решения "не делать X сейчас".
Формат: контекст → рассмотренные варианты → решение → последствия.

Зачем это нужно в pet-проекте: через полгода вы (или любой, кто откроет
репозиторий) не будете помнить, почему структура выглядит именно так.
ADR — это ответ, живущий в git рядом с кодом, а не в чьей-то памяти.

## Малая заметка (без отдельного ADR)

`utils/` также не заведён намеренно: это папка, которая на практике часто
превращается в свалку несвязанных функций. Вместо неё — именованные модули
по ответственности (например, `core/pagination.py`), когда появится
конкретный переиспользуемый код.
