# Helm-чарт TaskFlow

## Статус: параллельный, независимый способ развёртывания

Этот чарт НЕ используется для управления текущим рабочим кластером --
там приложение развёрнуто через raw-манифесты `infra/k8s/base/` (см.
`infra/k8s/README.md`), и они продолжают быть источником истины для
текущего kind-кластера.

Чарт написан и полностью проверен (`helm lint`, `helm template`,
реальная установка в изолированный `taskflow-helm-test` namespace),
но осознанно НЕ применён к рабочему namespace `taskflow` -- миграция
существующего кластера с raw-манифестов на Helm потребовала бы
отдельного аккуратного шага (риск временного простоя, необходимость
сохранить данные Postgres), а реальной выгоды от неё до появления
нового кластера нет.

## Когда этот чарт понадобится

При развёртывании на будущем кластере (Proxmox + k3s/kubeadm или любом
другом) -- тогда это будет ЕДИНСТВЕННЫЙ способ установки, одной
командой вместо пятнадцати отдельных файлов.

## Установка (на НОВОМ кластере, не текущем)

```bash
cp charts/taskflow/values-secrets.yaml.example charts/taskflow/values-secrets.yaml
# отредактировать values-secrets.yaml, подставить реальный пароль и JWT-ключ

helm install taskflow charts/taskflow \
  --namespace taskflow --create-namespace \
  -f charts/taskflow/values.yaml \
  -f charts/taskflow/values-secrets.yaml \
  --set gateway.className=kong
```

Требования на целевом кластере, применяемые ДО этой команды:
- Gateway API CRD установлены (`kubectl apply -f .../standard-install.yaml`)
- Kong (или иной Gateway API контроллер) установлен через `helm install kong ...`
- `GatewayClass` создан ЭТИМ чартом (шаблон `69-gatewayclass.yaml`), но с
  аннотацией `konghq.com/gatewayclass-unmanaged: "true"` -- требует уже
  установленного Kong рядом, а не провижинит его сам

## Найденные при разработке уроки (стоит помнить при следующей правке)

- `{{ }}` в YAML-комментариях интерпретируются Go-шаблонизатором Helm
  так же, как и настоящий код -- писать примеры синтаксиса внутри
  комментариев тем же синтаксисом нельзя, ловится только `helm lint`.
- Helm-хуки (`pre-install`) выполняются РАНЬШЕ вообще всех обычных
  ресурсов чарта, а не просто "раньше по порядку файлов", как было в
  raw-манифестах с числовыми префиксами имён. Job миграций поэтому --
  `post-install`/`post-upgrade`, а не `pre-*`, и с собственным
  `initContainer`, ожидающим готовности Postgres через `pg_isready`.
- `Namespace` и `GatewayClass` -- объекты, которые легко случайно
  оставить существующими вне управления Helm (созданными через
  `kubectl apply` в другом namespace/кластере) -- тогда `helm install`
  отказывается "импортировать" их без явных меток владения.
